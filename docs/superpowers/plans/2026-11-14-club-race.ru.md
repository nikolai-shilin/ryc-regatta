# План реализации клубной гонки

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Цель:** Организатор настраивает гонку, делится ссылкой, и участники клуба проходят её вместе вживую, а компьютерные
лодки добирают флот. Браузер организатора — судья, а если он отвалится, судейство берёт на себя браузер другого
участника.

**Архитектура:** `sim.js` учится вести гонку с несколькими лодками людей, передавать любую лодку компьютерному шкиперу,
а также сохранять и восстанавливать всю гонку. Новый клиент Supabase Realtime без зависимостей (`net.js`) и модуль
протокола без DOM (`club.js`) переносят зал ожидания, ввод, снимки, события, передачу судейства и итоговый протокол.
`club-ui.js` и небольшие правки в `main.js` и `world.js` выводят всё это на экран. На Next.js добавляются страницы
`/club/new`, `/club/<code>` и `/club/connect`. Сервер результатов (`iyt-test`) менять не нужно: он уже принимает старт
и результат для любого id гонки.

**Технологии:** Обычные ES-модули в `public/game/` (без сборки), Supabase Realtime поверх голого WebSocket (JSON-протокол
Phoenix v1), Next.js 16 App Router, `node:test`.

**Спецификация:** `docs/superpowers/specs/2026-11-14-club-race-design.md`

## Общие ограничения

- Работа идёт в ветке `club-race`, отрезанной от `main` после того, как владелец закоммитит незакоммиченные там
  изменения.
- `public/game/` остаётся ES-модулями без сборки. Игра не загружает ни одного пакета `@supabase/*`; `net.js` сам говорит
  на протоколе, и импортирует его только клубная гонка (динамический `import()`).
- Одиночная игра (гонка дня, свободная гонка) ведёт себя ровно как раньше: эталонный тест из Задачи 1 должен оставаться
  зелёным после каждой задачи.
- Проект Supabase `iyt-test` (`xpdhkahgvusuicynssxq`), тариф Pro: 500 сообщений/с, 500 подключений, 50 presence-сообщений/с
  на проект. Расчётный бюджет: около 110 сообщений в секунду на шесть участников и меньше 200 на десять. Presence не
  используется вовсе.
- Частоты: снимки 10 Гц. Полная копия гонки для передачи судейства — каждые 3 с. Ввод — при изменении, не чаще 10/с и не
  реже 2/с в простое. Приветствие в зале ожидания — каждые 3 с, во время гонки никогда.
- Каждая строка для пользователя есть на английском и русском (`t('…', '…')` на страницах; таблицы `T` в игре).
- Размер флота: от 2 до 10 лодок (`FLEET.length + 1`). Лимит времени: 600 с после финиша первой лодки. Удержание курса
  после 3 с без ввода; компьютерный шкипер — после 10 с. Передача судейства, когда 4 с не приходило ни одного снимка.
  Стартовать может любой, когда организатора нет в зале ожидания уже 120 с.
- Лодка человека, пересёкшая финиш, пока ею правит компьютер, получает DNF. Лодка, которая к лимиту времени ещё в гонке,
  получает DNF.
- `npm test`, `npm run typecheck` и `npm run build` проходят в конце каждой задачи.

## На что смотреть при проверке

1. **Телефон организатора уходит в фон сразу после нажатия Start** (его кадры анимации останавливаются). Ожидается:
   примерно через 5 с судьёй становится игра другого участника, и гонка продолжается. Когда организатор возвращается,
   его игра следует за новым судьёй и не спорит с ним. → Задача 6, `test: handover when the referee goes silent`.
2. **Вкладка участника уходит в фон посреди гонки, потом возвращается.** Ожидается: его лодка держит курс, затем ею
   правит компьютер. Вернувшись, участник снова рулит, и его лодка перескакивает туда, где её видит судья, а не туда,
   где её оставили. → Задача 5, `test: a silent member holds course, then the computer sails her, then she is given back`.
3. **Участники открывают ссылку раньше, чем появился организатор, или организатор так и не возвращается.** Ожидается:
   "Waiting for the organiser" («Ждём организатора»). Кнопка Start появляется у всех через 120 с после того, как
   организатора видели в последний раз. Участник, у которого страница загрузила другую акваторию, перезагружается в
   нужную. → Задача 4, `test: anyone may start once the organiser has been gone 120 s`.
4. **Участников больше, чем лодок, или кто-то приходит после старта.** Ожидается: идут первые `fleet` участников по
   времени входа. Остальные, а также все, кто пришёл после старта, смотрят. → Задача 4, `test: the fleet takes members by join time, the rest watch`.
5. **Два участника с одинаковым именем или с пустым именем.** Ожидается: пустое имя становится "No name" / "Без имени",
   а повторяющееся получает " 2", " 3" по времени входа, чтобы в протоколе их можно было различить. → Задача 4,
   `test: names are made unique`.

### Задача 1: Несколько лодок людей в симуляторе

**Файлы:**
- Изменить: `public/game/sim.js` (конструктор около 566–626, `record` 628, `step` 696, `progress` 737, `hails` 941,
  `foul` 953, `collide` 969, прикрытие в `drive` на 1147, `roomToTack` 1238, `youCanHail` 1263, `hail` 1279)
- Изменить: `public/game/main.js` (`handleMessages` ~1161; то, что читает `world.js`, здесь не меняется)
- Тест: `test/sim.test.mjs`

**Интерфейсы:**
- Даёт:
  - `new Race({ ...existing, humans?: { id: string, name: string }[], me?: string | null, club?: boolean })`.
    По умолчанию `humans = [{ id: 'you', name: 'You' }]`, `me = humans[0].id`.
  - `race.humans: Boat[]` в заданном порядке. У каждой лодки `b.human = true`, `b.id`, `b.name`, `b.log` (тот объект,
    что сегодня `this.log`) и `b.ai = null`. Первый человек занимает нынешнее место игрока. Человек *k* (k ≥ 1)
    занимает место компьютерной лодки *k* (`boats[k]`), у которой убирается `ai`. Вызовы `rand()` не меняются, так что
    гонка с одним человеком — та же гонка, что и раньше.
  - `race.player`: человек, у которого `id === me`. При `me === null` (зритель): `humans[0]` и `race.watching = true`.
  - `race.log`: геттер, `this.player.log`.
  - `race.say(key, arg, to = null)` добавляет `{ key, arg, to }`, где `to` — лодка (Boat) или `null` (для всех).
    Каждая существующая ветка `b === this.player` превращается в `b.human` с `to = b`.
  - `race.youCanHail(P = this.player)`, `race.hail(P = this.player)`. Оклик лодки человека сообщает ей `'hail'`
    `{ who: P.name, rule }`.
  - `hails()` работает для каждого человека. В `drive` прикрывать нужно ближайшую нефинишировавшую лодку человека на
    том же отрезке дистанции.
  - Толчея в `step` следует за ветром в средней точке нефинишировавших людей (всех людей, если нефинишировавших нет).

### Задача 2: Передача лодки компьютеру, DNF, лимит времени и собственный шаг участника

**Файлы:**
- Изменить: `public/game/sim.js`
- Тест: `test/sim.test.mjs`

**Интерфейсы:**
- Использует: `race.humans`, `b.human` из Задачи 1.
- Даёт:
  - `race.makeAi(b, i)`: нынешний объект `ai` для отдельной лодки, вынесенный из конструктора без изменения порядка
    вызовов `rand()` в нём.
  - `race.setComputer(b, on: boolean)`. Включение: `b.ai = race.makeAi(b, index)` со `skill: 0.85`, `b.autoTrim = true`,
    `b.computer = true` (лодкой в какой-то момент правил компьютер). Выключение: `b.ai = null`, а `b.autoTrim`
    возвращается к `b.ownTrim` (сохранённому при включении).
  - В `progress` человек, финишировавший с установленным `b.ai`, получает `b.dnf = true` и `place = null`.
  - С `club: true`: когда финиширует первая лодка, `race.limitT = clock + 600`. После `limitT` каждая ещё не завершившая
    лодка получает `done = true`, `dnf = true`, `finish = null`. `race.over` истинно, когда завершили все лодки (в
    одиночной игре смысл прежний).
  - `standings()`: сначала финишировавшие, затем DSQ, DNF в самом конце.
  - `race.stepView(dt, b)`: продвигает `clock`, `t`, ветер и волны ровно так же, как `step`, и делает шаг только для `b`
    (`b.step(dt, this)`) и её следа. Никаких `drive`, `progress`, правил и сигналов: на экране участника всё это
    приходит от судьи.

### Задача 3: Сохранение и восстановление гонки

**Файлы:**
- Изменить: `public/game/sim.js` (`rng`, `Race`)
- Тест: `test/sim.test.mjs`

**Интерфейсы:**
- Даёт:
  - `rng(seed)` возвращает функцию, у которой также есть `.get(): number` и `.set(s: number)` для доступа к её
    состоянию.
  - `race.snapshot(): object`: простой JSON всей гонки, кроме массивов `track` у лодок. Лодка (Boat), на которую
    ссылаются где-либо вне `race.boats`, записывается как `{ $boat: index }`, `Map` — как `{ $map: [[k, v], …] }`
    (ключи-лодки — как `{ $boat }`), rng — как `{ $rng: state }`, `Wind` — как `{ $wind: {…fields} }`, а `Boat` внутри
    `boats` — своими полями, без `_race`.
  - `Race.restore(state, tracks?: Record<string, [number, number][]>): Race` пересобирает гонку с правильными
    прототипами. Ключи `tracks` — имена лодок, а лодки, для которых следа нет, начинают с пустого.

### Задача 4: Клиент Realtime и зал ожидания

**Файлы:**
- Создать: `public/game/net.js`, `public/game/club.js` (часть с `Lobby`), `test/hub.mjs`, `test/net.test.mjs`,
  `test/club.test.mjs`, `scripts/realtime-smoke.mjs`

**Интерфейсы:**
- Даёт (`net.js`):
  - `realtime({ url, key, WebSocket = globalThis.WebSocket }) → { channel(topic, { self = false } = {}), close() }`.
  - `channel → { join(): Promise<void>, send(event, payload): void, on(event, fn(payload)): void, leave(): void }`.
  - Формат на проводе: сокет по адресу `${url with http→ws}/realtime/v1/websocket?apikey=${key}&vsn=1.0.0`. Кадры имеют
    вид `{ topic: 'realtime:' + topic, event, payload, ref, join_ref }`. Вход в канал — `phx_join` с
    `{ config: { broadcast: { self, ack: false }, presence: { key: '', enabled: false }, postgres_changes: [], private: false }, access_token: key }`.
    Отправка — событие `broadcast` с `{ type: 'broadcast', event, payload }`. Heartbeat уходит в топик `phoenix`
    (`heartbeat`) каждые 25 с. После закрытия клиент переподключается через 1, 2, 5, затем каждые 10 с и заново входит
    во все каналы. `send`, сделанный до ответа на вход в канал, отбрасывается.
- Даёт (`club.js`):
  - `makeLink(rt, code, myId) → { all: Channel /* 'club:'+code */, inputOf(id): Channel /* 'club:'+code+':in:'+id */ }`.
  - `new Lobby({ link, me: { id, name, look }, organiser: boolean, settings: object | null, now = () => Date.now() })`
    - Отправляет `hello { id, name, look, joinedAt, organiser, settings }` при входе и каждые 3 с; отправляет `bye { id }`
      при `leave()`.
